# Repository guidance

## Agent skills

### Issue tracker

Large specs use GitHub Issues; implementation tickets use local Markdown. Before creating, fetching, claiming, or updating work, read [docs/agents/issue-tracker.md](docs/agents/issue-tracker.md).

### Triage labels

Use the five default triage roles. Before assigning a triage role, read [docs/agents/triage-labels.md](docs/agents/triage-labels.md).

### Domain docs

Use single-context domain documentation. Before exploring domain behavior or proposing decisions, read [docs/agents/domain.md](docs/agents/domain.md).

## Collaboration

Before claiming work or resuming a session, read [context/README.md](context/README.md) and your own progress file. Update only your progress file unless coordinating an agreed shared change. Ticket files are authoritative for ownership, dependencies, and completion.

## Restricted material

Keep the handoff bundle, organizer data, competition code, submission contents, credentials, and private traces out of this public repository and public issues. Consult organizer material locally; access simulator state only through the official ToolEnv. Confirm repository visibility and authorized team access before publishing restricted material anywhere.
